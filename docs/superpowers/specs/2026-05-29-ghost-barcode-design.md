# Ghost Barcode Lookup — Design Spec

**Date:** 2026-05-29  
**Feature:** Ghost Barcode — automatic lookup of unrecognized barcodes  
**Approach:** Lazy resolution (Approach A) — record on scan failure, resolve when manager opens Products tab  
**Status:** Approved for implementation

---

## 1. Problem Statement

When a cashier scans a barcode that doesn't exist in the system, ZANPOS shows an error and moves on. The unrecognized barcode is lost — no one follows up. This means products that *should* be in the catalog never get added, and cashiers are forced to manually enter prices or abandon the scan.

**Goal:** Automatically record every unrecognized barcode, look it up online when a manager is ready to review, and let the manager create a properly-named product in one click.

---

## 2. User Stories

**Cashier:**  
> As a cashier, when I scan a barcode that's not in the system, I see the same error as before — but I know the system has recorded it for the manager to handle later.

**Manager:**  
> As a manager, when I open the Products tab in Back Office, I see a badge telling me there are unrecognized barcodes to review. I click "Look up now", see the product names and brands found online, and create any missing products in one click.

---

## 3. Architecture Overview

```
CASHIER SCAN FAILURE
  └─► record_unknown_barcode(barcode)
        └─► INSERT into unknown_barcodes (deduplicated)
              (scan_count incremented if already exists)

MANAGER OPENS PRODUCTS TAB
  └─► get_ghost_barcode_summary()
        └─► { pending: N, found: N }
              └─► Badge shown on Products nav item (manager/owner only)

MANAGER CLICKS "Look up now"
  └─► resolve_ghost_barcodes()
        └─► For each pending barcode:
              1. UPCitemdb API
              2. Open Food Facts API  (if #1 misses)
              3. AI fallback          (if #2 misses and AI key configured)
              └─► UPDATE status, store product_name/brand/category/image_url

MANAGER REVIEWS RESULTS
  ├─► "Create Product" → get_product_prefill_from_ghost(id)
  │     └─► Opens product form pre-filled with found data
  └─► "Dismiss" → dismiss_ghost_barcode(id)
        └─► status = 'dismissed', removed from panel
```

## 4. Database Schema

### Migration: `0025_unknown_barcodes.sql`

```sql
CREATE TABLE IF NOT EXISTS unknown_barcodes (
    id              TEXT PRIMARY KEY NOT NULL,
    barcode         TEXT NOT NULL UNIQUE,
    scan_count      INTEGER NOT NULL DEFAULT 1,
    first_seen_at   INTEGER NOT NULL,
    last_seen_at    INTEGER NOT NULL,
    status          TEXT NOT NULL DEFAULT 'pending'
                        CHECK(status IN ('pending','found','not_found','dismissed')),
    product_name    TEXT,
    brand           TEXT,
    category        TEXT,
    image_url       TEXT,
    raw_json        TEXT
);

CREATE INDEX IF NOT EXISTS idx_unknown_barcodes_status ON unknown_barcodes(status);
```

### Field Notes

| Field | Purpose |
|---|---|
| `id` | ULID — generated by Rust on INSERT |
| `barcode` | UNIQUE — same barcode scanned 10× produces 1 row, scan_count = 10 |
| `scan_count` | How many times this barcode failed — useful to prioritise busy products |
| `first_seen_at` / `last_seen_at` | Unix milliseconds |
| `status` | `pending` → awaiting lookup; `found` → API returned data; `not_found` → all sources failed; `dismissed` → manager dismissed |
| `product_name`, `brand`, `category`, `image_url` | Populated after successful lookup |
| `raw_json` | Full API response stored for debugging / future re-processing |

## 5. Rust Backend

### Module: `src/db/commands/ghost_barcode_commands.rs`

#### `record_unknown_barcode(barcode: String, state: State<AppState>)`
- Called by frontend immediately after a scan-not-found error
- `INSERT INTO unknown_barcodes (id, barcode, scan_count, first_seen_at, last_seen_at) VALUES (?, ?, 1, ?, ?)`  
  `ON CONFLICT(barcode) DO UPDATE SET scan_count = scan_count + 1, last_seen_at = excluded.last_seen_at`
- Returns `Ok(())` — fire and forget from frontend
- RBAC: none required (cashier-level)

#### `get_ghost_barcode_summary(state: State<AppState>) → GhostSummary`
```rust
pub struct GhostSummary {
    pub pending: i64,
    pub found: i64,
    pub not_found: i64,
}
```
- Simple `SELECT status, COUNT(*) FROM unknown_barcodes WHERE status != 'dismissed' GROUP BY status`
- RBAC: manager_or_owner

#### `list_ghost_barcodes(state: State<AppState>) → Vec<GhostBarcode>`
```rust
pub struct GhostBarcode {
    pub id: String,
    pub barcode: String,
    pub scan_count: i64,
    pub first_seen_at: i64,
    pub last_seen_at: i64,
    pub status: String,
    pub product_name: Option<String>,
    pub brand: Option<String>,
    pub category: Option<String>,
    pub image_url: Option<String>,
}
```
- Returns all non-dismissed barcodes, ordered by `scan_count DESC` (most-scanned first)
- RBAC: manager_or_owner

#### `resolve_ghost_barcodes(state: State<AppState>) → ResolveResult`
```rust
pub struct ResolveResult {
    pub resolved: i64,   // how many moved to 'found'
    pub not_found: i64,  // how many exhausted all sources
}
```
- Fetches all `status = 'pending'` barcodes
- For each, runs HTTP chain (see §6)
- Updates rows in place
- Returns summary counts
- RBAC: manager_or_owner
- Timeout per barcode: 5 seconds total across all sources

#### `dismiss_ghost_barcode(id: String, state: State<AppState>)`
- `UPDATE unknown_barcodes SET status = 'dismissed' WHERE id = ?`
- RBAC: manager_or_owner

#### `get_product_prefill_from_ghost(id: String, state: State<AppState>) → ProductPrefill`
```rust
pub struct ProductPrefill {
    pub name: String,
    pub barcode: String,
    pub brand: Option<String>,
    pub category: Option<String>,
    pub image_url: Option<String>,
}
```
- Reads the ghost barcode row and returns data shaped for the product creation form
- Does NOT create the product — frontend handles form pre-fill
- RBAC: manager_or_owner

## 6. HTTP Lookup Chain

Executed inside `resolve_ghost_barcodes`, sequentially per barcode, stopping at first hit.

### Tier 1 — UPCitemdb (free tier)
```
GET https://api.upcitemdb.com/prod/trial/lookup?upc={barcode}
```
- Parse: `response.items[0]` → `title` (product_name), `brand`, `category`, `images[0]` (image_url)
- Free tier: 100 requests/day (sufficient for typical retail ghost volume)
- On HTTP error or empty items array → fall through to Tier 2

### Tier 2 — Open Food Facts
```
GET https://world.openfoodfacts.org/api/v0/product/{barcode}.json
```
- Parse: `product.product_name`, `product.brands`, `product.categories_tags[0]`, `product.image_url`
- Free, no rate limit for reasonable usage
- On HTTP error or `status != 1` → fall through to Tier 3

### Tier 3 — AI Fallback (optional)
- Only runs if `app_config.ai_api_key` is set
- Prompt: `"The barcode {barcode} was scanned at a retail POS in Bahrain but was not found in our product database. Based on this barcode, can you identify: product name, brand, category? Reply in JSON: {\"product_name\": \"\", \"brand\": \"\", \"category\": \"\"}"`
- Direct `reqwest` POST to the configured AI API endpoint using the same API key from `app_config` — NOT the chat session infrastructure in `ai_commands.rs` (which is stateful/streaming). This is a single one-shot completion request.
- On failure or no key → status = `not_found`

### Error Handling
- Any network error sets that tier as failed and falls through
- If all tiers fail → `status = 'not_found'`
- Each barcode lookup is independent — one failure doesn't stop others
- All updates are wrapped in a transaction per barcode

## 7. Frontend

### Badge on Products Nav Item

In the Back Office nav, the Products tab item gains an optional badge:
- Calls `get_ghost_barcode_summary()` on Back Office mount
- Shows orange badge with count if `pending + found > 0`
- Only rendered for manager/owner role
- Badge clears when all barcodes are dismissed or turned into products

### Ghost Barcodes Panel (`GhostBarcodesPanel.tsx`)

Rendered at the top of the Products tab (Back Office), collapsible:

**States:**
1. **No ghosts** — panel hidden
2. **Pending ghosts** — shows "N unrecognized barcodes recorded. [Look up now]"
3. **Loading** — spinner while `resolve_ghost_barcodes` runs
4. **Results** — list of cards, one per barcode:
   - Found: product name, brand, category, thumbnail if image_url exists → **[Create Product]** + **[Dismiss]**
   - Not found: barcode string, scan count, "Not found in any database" → **[Dismiss]**
5. **All dismissed** — panel collapses

**"Create Product" flow:**
- Calls `get_product_prefill_from_ghost(id)` → receives `ProductPrefill`
- Navigates to product creation form with fields pre-filled
- After product is saved, calls `dismiss_ghost_barcode(id)` to clean up the ghost entry

### Scan Failure Integration (PosPage.tsx)

In the existing barcode scan error handler, add one call after the error is shown:
```typescript
// After showing scan error to cashier:
recordUnknownBarcode(barcode).catch(() => {}); // fire and forget
```

## 11. Out of Scope (this spec)

- Automatic background resolution without manager triggering (Approach B) — deferred
- Rate-limit handling for UPCitemdb paid tiers — free tier sufficient at launch
- Barcode lookup history / audit log — barcodes are ephemeral until turned into products
- Bulk "Create All" button — one-by-one gives manager control over pricing
